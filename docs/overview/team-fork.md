# 团队版独立二开

本仓库由 [tigerowo/infinite-canvas](https://github.com/tigerowo/infinite-canvas) fork 后独立开发。参考和复用其画布、媒体节点与创作功能，团队业务按新的项目规则设计。上游起点为 `c51c49d2110e84c6dabefba6480df8561bc3eed5`，原版 `v0.8.0`；开发分支为 `codex/team-studio`，原作者、标识与 AGPL-3.0 LICENSE 保留。

## 当前范围

2026-10-09：U00源码接入与U01管理者创建分派已完成限定本机验收。沿用Go/Gin/GORM和Next.js/React，新增ProductionProject，不把个人CanvasProject作为业务项目。

- 默认入口 `/projects`，管理者获得两项独立权限后创建项目并选择active普通账号负责人；管理员默认有操作权限，仍不自动读取别人的项目。
- 项目创建、两个canvas/assets空间与requestId去重同事务；改派revision条件更新，旧负责人之后列表/项目/空间拒绝访问；受项目引用的账号不能删除。
- 真实项目库、概览与两工作台授权容器，创建/返回/切换/刷新/改派闭合。容器尚未接入编辑器或资产内容。
- 失败保留输入，创建响应丢失后同键重试，改派冲突须明确重新载入；登录与项目回执受会话/路由校验，离页不留授权缓存；对话框双向Tab循环与焦点返回。
- 旧个人创作路径由Next服务端导向项目库，原编辑器源码/数据保留。旧个人API尚未改造成项目接口，不能作为已隔离内容入口使用。
- 登录/第三方资料/原余额调整仅定向写对应字段，保护项目权限；这不代表原积分日志已事务化或账本模块完成。

本机Go/Bridge/Next构建与独立tsc通过；16组API/347请求、13组浏览器、14张截图和1440×900/1280×720开发者目视通过。包括20同键创建只得1项目/2空间、20同版本改派1成功/19冲突、中途故障完整回滚和重启恢复。网页/账号/数据库均为独立临时验收，未配置模型或执行收费生成；客户视觉认可仍待反馈。

验证脚本与原始证据位于外层工作区 `tools/verify-production-project-{api,ui}.mjs` 和 `output/rebuild/verification/U01/`，不随本仓库发布。数据库模型见[数据库说明](../backend/backend-database.md)，人工/生产待验见[待测试](../progress/pending-test.md)。

U00保留的启动兼容：`CANVAS_BIND_HOST`本机设127.0.0.1；`CANVAS_DISABLE_PROMPT_SYNC=true`禁用提示词定时抓取；Next文件追踪/Turbopack root固定web目录。上游作者、页面来源标识和LICENSE保留。

## 后续业务方向

业务项目由拥有创建和分派权限的管理者创建，必须指定制作负责人。制作人员只进入被分派项目，再选择画面创作或资产创意。两工作台共用项目身份，文档、资产、文件与任务明确属于项目。

U01完成后停止；下一候选U02只接入项目内画布文档和版本条件保存，需用户下一轮继续。原生个人CanvasProject将逐步定位为项目内文档；图片参数/历史、资产与文件各有后续模块。

之后分别处理文档归属与保存冲突、项目资源和私有下载授权、可靠异步任务、积分预占与追加账本、剧本分析。数据库权威任务/outbox、有界并发、幂等终结、失败恢复和20人联合负载需要逐项实现并验收；上游已有异步代码不等于容量验证。原型、本机测试、用户验收和生产上线分别记录。
