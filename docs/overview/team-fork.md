# 团队版独立二开

本仓库由 [tigerowo/infinite-canvas](https://github.com/tigerowo/infinite-canvas) fork 后独立开发。参考和复用其画布、媒体节点与创作功能，团队业务按新的项目规则设计。上游起点为 `c51c49d2110e84c6dabefba6480df8561bc3eed5`，原版 `v0.8.0`；开发分支为 `codex/team-studio`，原作者、标识与 AGPL-3.0 LICENSE 保留。

## 当前范围

当前只接入独立源码并验证本机运行。后端沿用 Go/Gin/GORM 的 handler、service、repository、model 分层；前端沿用 Next.js/React/TypeScript 的现有结构，不重新搭建空编辑器。一次完成一个小模块，构建、必要测试、桌面交互检查后停止。

本轮必要修改：

- `CANVAS_BIND_HOST` 控制后端监听地址，默认保持上游行为，本机预览设为 `127.0.0.1`。
- `CANVAS_DISABLE_PROMPT_SYNC=true` 可禁止创建提示词抓取定时器；默认保持上游行为。
- Next 的文件追踪与 Turbopack 根目录固定为 `web/`，使源码放在其他项目目录中时仍生成独立 standalone 服务。standalone 运行需按原文档复制 public 和 `.next/static`。
- 账号首次登录后确认同步权限、等待浏览器持久层加载，再读取云端画布；取消已退出或被替换会话的同步回写。

本轮仅用合成文本节点验证访客本地存储和账号服务端同步，不配置真实模型，不执行收费生成、素材上传或生产部署。待用户验证项见[待测试](../progress/pending-test.md)。

## 后续业务方向

业务项目由拥有创建和分派权限的管理者创建，必须指定制作负责人。制作人员只进入被分派项目，再选择画面创作或资产创意。两工作台共用项目身份，文档、资产、文件与任务明确属于项目。

下一模块仅完成管理者创建分派和统一项目入口。原生个人 CanvasProject 将逐步定位为项目内画布文档；原生个人画布库与图片页尚不具备上述团队项目规则。

之后分别处理文档归属与保存冲突、项目资源和私有下载授权、可靠异步任务、积分预占与追加账本、剧本分析。数据库权威任务/outbox、有界并发、幂等终结、失败恢复和20人联合负载需要逐项实现并验收；上游已有异步代码不等于容量验证。原型、本机测试、用户验收和生产上线分别记录。
